# 학식 고도화 계획

## 목표

학생이 앱을 켜자마자 오늘 먹을 메뉴를 고르고, 이전 평가를 통해 실패 확률을 줄인다.

## 대상 식당

- 진리관: 매주 월요일 공식 식단을 크롤링한다.
- 교직원: 매주 월요일 공식 식단을 크롤링한다.
- 푸드코트: 정적 메뉴를 직접 입력한다.

## 데이터 흐름

```text
월요일
공식 식단 크롤링
-> 날짜 / 식당 / 식사 / 메뉴별로 DB 저장
-> 메인 메뉴 자동 판별
-> 앱에서 오늘 식단 표시

사용자 평가
-> 식사 시작 후부터 3일 뒤 자정까지 가능
-> 오늘 평가와 역대 평가를 함께 집계 및 표시
```

## 메뉴와 평가 규칙

- 같은 메뉴가 다른 날짜에 다시 나오면 새롭게 평가할 수 있다.
- 역대 평가는 같은 식당의 같은 메뉴명을 기준으로 누적한다.
- 평가는 `좋았어요` 또는 `아쉬웠어요` 중 하나다.
- 한 사용자(익명 식별자 또는 로그인 계정)는 같은 날짜, 식사, 메뉴에 한 번만 평가할 수 있다.
- 사용자는 자신의 평가를 변경할 수 있다.
- 비로그인 사용자도 익명 앱 또는 브라우저 식별자로 평가할 수 있다.
- 로그인 기능을 도입하면 기존 익명 평가를 계정에 연결할 수 있다.

## 메인 메뉴 판별

모든 메뉴를 보여 주되, 평가 버튼은 메인 메뉴와 국에만 표시한다.

- 제외 키워드: 밥, 김치, 깍두기, 단무지, 나물, 샐러드, 음료, 후식, 소스 등
- 평가 후보 키워드: 제육, 불고기, 돈까스, 닭갈비, 찌개, 탕, 덮밥, 비빔밥, 볶음밥, 카레, 면, 파스타, 치킨, 국 등
- `비빔밥`, `볶음밥`, `덮밥`은 밥이 포함되어도 메인 메뉴로 인정한다.
- 자동 판별이 애매하면 평가 버튼을 표시하지 않는다.
- 나중에 관리자가 주간 메뉴의 평가 대상 메뉴를 직접 수정할 수 있게 한다.
- 푸드코트 메뉴는 입력할 때부터 모두 평가 가능 메뉴로 지정한다.

## UI 원칙

- 식당은 진리관, 교직원, 푸드코트 탭으로 즉시 전환한다.
- 조식, 중식, 석식은 명확히 분리한다.
- 메인 메뉴 아래에 오늘 평가와 역대 평가를 두 줄로 표시한다.
- 평가는 `좋았어요`, `아쉬웠어요` 아이콘 버튼 두 개만 제공한다.
- 평가 수가 적을 때는 비율보다 실제 평가 인원을 우선 표시한다.
- 식사 시작 전에는 평가 버튼을 비활성화하고, 평가 가능 시간을 안내한다.
- 평가 후에는 사용자의 현재 선택 상태를 표시한다.
- 푸드코트는 업체별로 묶고 메뉴명과 가격을 표시한다.
- 품절 기능은 이번 범위에서 제외한다.

## 예외 처리

- 크롤링에 실패하거나 공식 홈페이지에 식단이 등록되지 않은 경우: `이번 주 식단이 아직 업데이트되지 않았어요.`를 표시한다.
- 메뉴 제공 정보가 없으면 평가 버튼을 표시하지 않는다.
- 새 크롤링 결과가 들어와도 기존 메뉴 제공 회차와 평가 기록은 삭제하지 않는다.

## 구현 우선순위

1. 메뉴 항목, 메뉴 제공 회차, 평가 테이블을 추가한다.
2. 월요일 크롤링 결과를 메뉴 단위로 DB에 저장한다.
3. 푸드코트 정적 메뉴 입력 구조를 만든다.
4. 메인 메뉴 자동 판별 규칙을 적용한다.
5. 오늘 및 역대 평가 집계 API를 만든다.
6. 익명 사용자 식별과 중복 평가 제한을 구현한다.
7. 학식 UI에 평가와 통계를 표시한다.
8. 크롤링 실패 문구와 관리용 메인 메뉴 수정 기능을 추가한다.

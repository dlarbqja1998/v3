# 메인 날씨 위젯 기획

## 1. 목적

골라바유 메인 지도에 고려대학교 세종캠퍼스의 현재 날씨를 빠르게 확인할 수 있는 세로형 위젯을 제공한다. 사용자가 메인에 진입했을 때 지도와 기존 생활 정보를 방해하지 않으면서 현재 기온과 날씨 상태를 즉시 판단하게 하는 것이 목표다.

이번 기능은 날씨 전문 화면이 아니라 지도 위 요약 위젯이다. 미세먼지, 위치 검색, 시간별·주간 예보, 기상특보 상세 화면은 포함하지 않는다.

## 2. 확정된 UI

- 위젯은 메인 바텀시트 최소 단계의 왼쪽 위에 배치한다.
- 위젯은 바텀시트 DOM 바깥의 지도 오버레이로 유지한다.
- 바텀시트가 중간·최대 단계로 올라가거나 학식·셔틀·건물 시트로 전환되어도 위젯 좌표는 이동하지 않는다.
- 열린 바텀시트가 위젯 영역을 덮는 것은 허용한다.
- 위젯 배경은 반투명 흰색, 텍스트는 어두운 브랜드 색상으로 표시한다.
- 위젯은 호이 이미지, 현재 기온, 상태 문구만 표시한다.
- 첫 운영 버전에서는 위젯을 눌렀을 때 별도 화면이나 상세 시트를 열지 않는다.

현재 UI 시안의 `28° / 맑음` 고정 데이터는 실제 API 연동 후 제거한다.

## 3. 위치 기준

사용자 GPS나 지도 중심 좌표를 사용하지 않고 고려대학교 세종캠퍼스 한 지점으로 고정한다.

```txt
표시 위치: 고려대학교 세종캠퍼스
기준 위도: 36.6095
기준 경도: 127.2870
기상청 격자 X: 66
기상청 격자 Y: 107
```

이 방식은 위치 권한, 개인정보 처리, 지도 이동에 따른 재요청, 사용자별 캐시 분리를 만들지 않는다. 웹과 Capacitor 앱 모두 동일한 캠퍼스 날씨를 표시한다.

## 4. 데이터 제공자

기상청 단기예보 조회서비스를 사용한다.

- 초단기실황 `getUltraSrtNcst`: 현재 기온과 현재 강수 형태
- 초단기예보 `getUltraSrtFcst`: 가장 가까운 예보 시각의 하늘 상태와 강수 형태
- 응답 형식: JSON
- 인증키 환경 변수: `KMA_SERVICE_KEY`

인증키는 Cloudflare Worker의 비공개 환경 변수로만 관리한다. Svelte 화면, 브라우저 번들, Capacitor 앱과 API 응답에는 인증키를 포함하지 않는다.

## 5. 골라바유 API 경계

클라이언트는 기상청 API를 직접 호출하지 않고 골라바유 API만 호출한다.

```http
GET /api/weather/current
```

정상 응답 형식은 다음과 같다.

```json
{
  "temperature": 28,
  "status": "맑음",
  "icon": "clear",
  "observedAt": "2026-08-13T13:00:00+09:00",
  "fetchedAt": "2026-08-13T13:47:00+09:00",
  "stale": false
}
```

`temperature`는 정수로 반올림한다. `status`와 `icon`은 서버에서 판정하여 클라이언트가 기상청 원본 코드를 해석하지 않게 한다.

웹에서는 같은 출처의 `/api/weather/current`를 호출한다. Capacitor 번들 앱에서는 운영 Cloudflare API 주소를 환경 설정으로 주입하여 동일한 HTTPS 응답 계약을 사용한다.

## 6. 발표 시각 선택

기상청 데이터가 아직 게시되지 않은 발표 시각을 요청하지 않도록 한국 시간 기준 안전 여유를 둔다.

- 초단기실황은 매시 40분 이후에 현재 시각의 정시 발표값을 요청하고, 그 전에는 이전 시간 정시 값을 요청한다.
- 초단기예보는 매시 45분 이후에 현재 시각의 30분 발표값을 요청하고, 그 전에는 이전 시간의 30분 발표값을 요청한다.
- 초단기예보 항목 중 현재 시각 이후 가장 가까운 예보 시각의 `SKY`와 `PTY`를 사용한다.
- 모든 시각 계산은 `Asia/Seoul`을 기준으로 하며 테스트에서는 현재 시각을 주입할 수 있게 한다.

## 7. 호이 아이콘 판정

판정 우선순위는 `눈 → 비 → 더움 → 하늘 상태`로 한다. 사용자의 행동에 직접 영향을 주는 강수 정보를 고온보다 우선한다.

| 조건 | 상태 문구 | 아이콘 키 | 이미지 |
|---|---|---|---|
| `PTY`가 눈·진눈깨비 계열 | 눈 | `snow` | `/images/weather/hoi-snow.webp` |
| `PTY`가 비·소나기 계열 | 비 | `rain` | `/images/weather/hoi-rain.webp` |
| 강수 없음, 현재 기온 30℃ 이상 | 더움 | `hot` | `/images/weather/hoi-hot.webp` |
| `SKY=1` | 맑음 | `clear` | `/images/weather/hoi-clear.webp` |
| `SKY=3` | 구름많음 | `mostly-cloudy` | `/images/weather/hoi-mostly-cloudy.webp` |
| `SKY=4` | 흐림 | `cloudy` | `/images/weather/hoi-cloudy.webp` |

초단기예보의 강수 형태는 다음처럼 축약한다.

- 비: `1`, `4`, `5`
- 눈: `2`, `3`, `6`, `7`
- 없음: `0`

비와 눈이 섞인 상태는 보유한 6종 아이콘 범위에서 `눈`으로 표시한다. 더움 기준은 첫 운영 버전에서 30℃로 고정하고, 체감온도나 폭염특보는 후속 기능으로 분리한다.

## 8. 캐시와 비용 제어

기존 `GOLABAU_CACHE` KV를 재사용한다.

```txt
캐시 키: weather:campus:current:v1
신선 기준: 캐시에 기록된 실황 발표 시각과 예보 발표 시각이 현재 요청해야 할 두 발표 시각과 모두 일치
오래된 데이터 허용: 마지막 정상 데이터로부터 6시간
KV 보관 TTL: 24시간
```

요청 흐름은 다음과 같다.

1. 현재 요청해야 할 실황·예보 발표 시각이 캐시에 기록된 두 발표 시각과 모두 일치하면 즉시 반환한다.
2. 데이터가 오래됐지만 6시간 이내이면 이전 데이터를 `stale: true`로 반환하고 `platform.context.waitUntil`에서 갱신한다.
3. 캐시가 전혀 없으면 기상청을 동기 호출하여 첫 데이터를 만든다.
4. 동시에 여러 갱신이 발생하면 서버 프로세스 안의 단일 갱신 Promise를 공유하여 중복 호출을 줄인다.
5. KV가 없는 로컬 개발 환경에서는 메모리 캐시를 사용한다.

별도 날씨 Cron은 추가하지 않는다. 사용자가 접속하지 않는 시간에는 외부 API를 호출하지 않는다.

한 시간에 실황과 예보를 각각 한 번 갱신한다고 가정하면 외부 호출은 최대 약 48회/일, 약 1,440회/월이다. KV 쓰기는 최대 약 24회/일이다. 사용자 수가 늘어도 외부 기상청 호출량은 발표 시각 수에 가깝게 유지된다.

## 9. 클라이언트 로딩

날씨는 메인 서버 렌더링을 막지 않고 클라이언트에서 지연 로딩한다.

1. 지도, 헤더, 바텀시트와 날씨 위젯 틀을 먼저 렌더링한다.
2. 초기 위젯은 이미지 없이 `--° / 확인 중`을 표시한다.
3. 마운트 후 `/api/weather/current`를 한 번 호출한다.
4. 정상 응답이면 호이 이미지, 기온, 상태를 교체한다.
5. API 요청은 동일 페이지 생명주기에서 중복 실행하지 않는다.

날씨가 메인 진입 목적에 필요한 정보이므로 메인 진입 시 한 번 요청하되, 폴링은 하지 않는다. 사용자가 페이지를 계속 열어 둔 상태에서 자동 갱신하는 기능은 첫 버전에서 제외한다.

## 10. 실패 처리

### 서버

- 기상청 실패와 6시간 이내 캐시가 있으면 이전 데이터를 `stale: true`로 반환한다.
- 정상 캐시가 전혀 없으면 `503`과 안전한 오류 코드만 반환한다.
- 기상청 원본 오류 메시지와 인증키는 사용자 응답에 포함하지 않는다.
- 외부 요청에는 타임아웃을 적용한다.
- 기상청 응답의 결과 코드, 필수 항목, 숫자 형식을 검증한다.

### 클라이언트

- 처음부터 실패하면 이미지 없이 `--° / 확인 불가`를 표시한다.
- 화면에 정상 데이터가 표시된 뒤 재요청이 실패하더라도 기존 데이터를 제거하지 않는다.
- `stale: true` 데이터는 계속 표시하되 접근성 설명에 `이전 관측 정보`임을 포함한다.
- 호이 이미지 로딩이 실패해도 기온과 상태 문구는 유지한다.

## 11. 구성 단위

역할이 섞이지 않도록 다음 단위로 분리한다.

- `src/lib/domain/weather.ts`: 날씨 타입, 기상청 코드 정규화, 호이 아이콘 판정
- `src/lib/server/weather.ts`: 발표 시각 계산, 기상청 호출, 응답 검증
- `src/lib/server/weather-cache.ts`: KV·메모리 캐시와 stale-while-revalidate
- `src/routes/api/weather/current/+server.ts`: 공개 API 응답과 HTTP 상태 처리
- `src/lib/weather/WeatherWidget.svelte`: 위젯 표시 상태와 접근성
- `src/routes/+page.svelte`: 위젯 위치와 한 번의 지연 로딩 연결

위젯의 위치 계산은 기존 `bottom-sheet.ts`의 고정 위치 계산을 계속 사용한다.

## 12. 검증 항목

### 단위 테스트

- 한국 시간과 분 경계에 따른 실황·예보 발표 시각 계산
- 기상청 `SKY`, `PTY`, `T1H` 응답 파싱
- 눈·비·더움·맑음·구름많음·흐림의 우선순위
- 29℃와 30℃의 더움 경계
- 비가 오는 30℃ 이상 날씨에서 비가 우선되는지 확인
- 신선 캐시, 오래된 캐시, 캐시 없음 분기
- 동시 갱신 요청 합치기
- 기상청 오류와 불완전한 응답 거부

### 화면 검증

- 로딩, 정상, 이전 관측, 확인 불가 상태
- 360px, 390px, 430px 화면 폭
- 바텀시트 최소·중간·최대 단계에서 위젯 좌표 유지
- 학식·셔틀·건물 시트 전환 시 좌표 유지
- 40px 수준에서도 호이 날씨 상태가 구분되는지 확인
- 일반 웹과 Capacitor WebView에서 HTTPS API 호출 및 이미지 표시 확인

### 전체 검증

- `npm test`
- `npm run check`
- `npm run build`

## 13. 제외 범위

- 사용자 GPS 기반 날씨
- 지도 중심에 따라 변하는 날씨
- 미세먼지와 초미세먼지
- 자외선, 습도, 풍속, 체감온도 표시
- 시간별·주간 예보 상세 화면
- 날씨 위젯 클릭 동작
- 기상특보 배지와 푸시 알림
- 자동 폴링과 날씨 Cron
- Neon DB 저장

## 14. 완료 기준

- 메인 진입 후 고려대학교 세종캠퍼스의 실제 기온과 상태가 표시된다.
- 여섯 종류의 호이 이미지가 서버 판정 결과와 정확히 연결된다.
- 기상청 인증키가 클라이언트에 노출되지 않는다.
- 날씨 요청이 메인 서버 렌더링을 지연시키지 않는다.
- 외부 API 장애 시 오래된 데이터 또는 명확한 실패 상태를 제공한다.
- 바텀시트의 모든 단계와 모드에서 위젯 고정 위치가 유지된다.
- 전체 테스트, Svelte 검사와 Cloudflare 빌드가 통과한다.

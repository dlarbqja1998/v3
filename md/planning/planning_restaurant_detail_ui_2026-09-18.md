# 음식점 상세와 지도 연결 개선

## 화면 구성

- 교외 원형 핀은 기본 상태에서 흰 바탕과 크림슨 테두리·기호, 선택 상태에서 크림슨 채움과 흰 기호를 사용한다.
- 음식점 상세는 기본 정보 → KU멤버십 혜택 → 운영시간 → 메뉴 순서다. 전화번호를 네이버지도 왼쪽에 표시하고 `tel:`로 연결한다. 0507 안심번호도 지원한다.
- 운영시간·메뉴 제목은 18px 굵게 표시하고 바로 옆에 같은 20px 꺾쇠 아이콘을 둔다. 둘 다 기본적으로 접혀 있으며 오늘 운영시간은 계속 보인다. 펼치기·접기 문구는 화면에서 제거하고 스크린리더용 이름과 상태로만 제공한다.
- 메뉴는 이름과 가격으로 정리했다. 메뉴별 부가설명은 표시하지 않는다. 배달 메뉴의 가격 기준 표시는 유지한다.
- KU멤버십의 학생증 제시 안내와 총학생회 출처 행은 제거하고 매장별 혜택과 개별 조건은 유지한다.
- 큰 섹션 경계는 화면 전체 폭의 1px `brand-section-border`(#c8bec2) 선과 24px 여백으로 통일한다. 교내 시설 상세에도 같은 클래스를 적용하고 AGENTS.md의 GB1 지침에 기록했다.

## 상세 전환과 캐시

기존에는 목록 클릭 후 SvelteKit 상세 데이터 요청이 완료되어야 화면을 전환했다. 이제 기본 정보는 목록 데이터로 바로 표시하고 나머지 상세를 이어서 가져온다. 조회 실패 시 같은 화면에서 다시 시도할 수 있고, 조회 중 뒤로 가면 늦게 도착한 응답이 상세를 다시 열지 않는다.

화면에 보이는 목록과 근처 행만 미리 읽으며 동시 미리 읽기는 2개로 제한한다. 클라이언트는 매장별 1분, 최대 80개를 보관한다. 서버도 매장별 1분, 최대 128개를 보관하고 같은 매장의 동시 요청을 합친다. 서버 캐시에는 사용자 인증 정보를 넣지 않으며 DB와 한국 날짜가 다르면 별도 키를 사용한다. 멤버십 조회도 상세 매장 하나로 제한했다.

로컬의 같은 상세 데이터 경로에서 반복 요청 시간이 약 220ms에서 캐시가 있는 경우 6~7ms로 줄었다. 새 미리 읽기 경로는 캐시가 있는 경우 2~10ms였다. 개발 서버에서 측정한 값이며 최초 DB 조회나 통신 자체의 시간이 0이 되는 것은 아니다.

## 지도에서 보기

기본 정보에 `골라바유 지도에서 보기`를 추가했다. 해당 가게의 구역을 열고 18배율로 위치를 맞추며, 선택 핀과 가게 한 개 목록을 표시한다. 핀은 상단 필터와 바텀시트 사이의 중앙에 위치한다. 상세 주소를 직접 열었다가 지도에 들어가거나 지도 주소를 새로고침해도 같은 가게를 찾는다. 일반 뒤로 가기는 원래 목록과 스크롤을 복원한다.

## 검증

- 캐시 만료·중복 요청·실패 재시도·한국 날짜 변경, 로컬 미리보기 제한, 지도 위치 계산과 기존 관련 동작을 포함해 17개 파일의 테스트 79개 통과.
- 타입 검사 오류 0개, 경고 0개.
- 최종 변경으로 Vite 클라이언트·서버 빌드와 Cloudflare 어댑터 빌드 통과. 로컬 서버는 5173 포트에서 다시 실행 중이다.
- 390px 모바일 화면에서 가로 넘침 없음, 교내·교외 전체 폭 구분선, 전화 링크, 메뉴 설명 제거, 동일한 여닫기 아이콘을 확인했다.
- 상세에서 지도 이동, 선택 핀의 크림슨 채움과 위치, 목록 복귀 및 브라우저 앞으로 가기를 확인했다.
- 실제 매장에 전화를 걸지는 않았다. 전화 링크 형식과 표시를 검증했다.

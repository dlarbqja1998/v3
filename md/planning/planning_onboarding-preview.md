# 관리자 온보딩 미리보기 기획

## 목적

골라바유 UI 디자인 담당자가 신규 사용자의 온보딩 흐름을 관리자 계정에서 반복해서 확인할 수 있도록, 실제 저장이 발생하지 않는 관리자 전용 미리보기를 제공한다.

## 사용자 흐름

1. 관리자가 마이페이지에 진입한다.
2. 관리자에게만 표시되는 `온보딩 미리보기` 버튼을 누른다.
3. `/admin/onboarding-preview`에서 신규 사용자와 같은 빈 온보딩 화면을 확인한다.
4. 닉네임 입력과 단과대·학과·학번·성별 선택, 이전·다음 이동을 실제 흐름과 동일하게 조작한다.
5. 어느 단계에서든 `미리보기 나가기` 버튼으로 관리자 마이페이지에 돌아간다.
6. 마지막 `시작하기` 버튼을 눌러도 서버 요청이나 DB 저장은 발생하지 않고, 저장되지 않는 미리보기임을 안내한다.

## 화면 구성

### 관리자 마이페이지

- `핀 수정하기`와 같은 관리자 전용 작업 영역에 `온보딩 미리보기` 버튼을 추가한다.
- 관리자 역할에서만 버튼을 노출한다.
- 일반 사용자의 마이페이지 구성은 변경하지 않는다.

### 온보딩 미리보기

- 실제 `/register` 온보딩과 같은 제목, 설명, 진행 표시, 입력·선택 UI, 이전·다음·시작하기 버튼을 사용한다.
- 미리보기는 신규 사용자 관점의 빈 값과 첫 단계에서 시작한다.
- 상단에 관리자 미리보기임을 알리는 짧은 표시와 `미리보기 나가기` 버튼을 둔다.
- `미리보기 나가기`는 `/my`로 이동하며 확인 대화상자를 띄우지 않는다.
- 마지막 `시작하기` 버튼은 실제 버튼의 문구와 모양을 유지한다.
- 미리보기에서 `시작하기`를 누르면 흰색 배경, 크림슨 아이콘과 테두리를 사용하는 공통 스타일의 안내 토스트를 표시한다.
- 안내 토스트 문구는 `미리보기에서는 정보가 저장되지 않습니다.`로 한다.

## 구현 구조

### 공통 온보딩 화면

- 현재 `src/routes/register/+page.svelte`에 포함된 단계별 UI와 클라이언트 상태를 공통 온보딩 컴포넌트로 분리한다.
- 공통 컴포넌트는 실제 가입 모드와 관리자 미리보기 모드를 명시적인 속성으로 구분한다.
- 실제 가입 모드에서는 기존 POST 제출과 검증 실패 값 복원을 유지한다.
- 미리보기 모드에서는 폼 제출을 만들지 않고 마지막 동작을 클라이언트 안내로 끝낸다.
- 두 모드가 동일한 단계 데이터와 선택 항목을 사용해 디자인이 서로 달라지지 않게 한다.

### 관리자 전용 경로

- `src/routes/admin/onboarding-preview/+page.server.ts`에서 로그인 여부와 `admin` 역할을 서버에서 확인한다.
- 로그인하지 않은 사용자는 `/login?next=/admin/onboarding-preview`로 이동한다.
- 로그인했지만 관리자가 아닌 사용자는 `/`로 이동한다.
- 미리보기 서버 로드는 DB를 조회하거나 변경하지 않는다.

### 권한 표시

- 마이페이지의 관리자 기능 표시 조건은 공통 권한 함수로 유지한다.
- 링크를 숨기는 것과 별개로 미리보기 라우트 자체에서도 관리자 권한을 다시 확인한다.

## 데이터 및 비용

- 미리보기 입력값은 브라우저 메모리에만 존재하며 새로고침하거나 나가면 사라진다.
- 관리자 사용자의 현재 프로필 정보는 미리보기에 넣지 않는다.
- POST 요청, Neon DB 조회·수정, Cloudflare KV 접근, 외부 API 호출을 추가하지 않는다.
- 따라서 화면 진입 외에 서버리스 데이터 비용은 발생하지 않는다.

## 모바일 및 접근성

- 320~430px 모바일 폭과 Capacitor WebView에서 기존 온보딩의 세로 흐름을 유지한다.
- `미리보기 나가기`는 상단 안전 영역을 침범하지 않고 항상 누를 수 있는 위치에 둔다.
- 뒤로 가기는 브라우저와 Capacitor의 기본 탐색 흐름에 따라 이전 마이페이지로 복귀할 수 있게 한다.
- 안내 토스트에는 `role="status"`와 `aria-live="polite"`를 적용한다.
- 토스트는 하단 버튼과 안전 영역을 가리지 않는 위치에 표시하고 짧은 이동·투명도 전환만 사용한다.

## 오류 및 예외 처리

- 비관리자의 직접 URL 접근은 서버 권한 검사로 차단한다.
- 미리보기에서는 네트워크 요청이 없으므로 저장 실패 상태를 만들지 않는다.
- 마지막 단계에서 필수 선택이 완료되지 않으면 실제 온보딩과 동일하게 `시작하기` 버튼을 비활성화한다.
- 빠르게 여러 번 눌러도 토스트와 제거 타이머는 하나만 유지한다.

## 검증

- 관리자 역할에만 마이페이지의 `온보딩 미리보기` 링크가 표시되는지 확인한다.
- 비로그인 사용자와 일반 사용자가 관리자 미리보기 경로에 접근할 수 없는지 확인한다.
- 미리보기의 다섯 단계를 실제 온보딩과 동일한 선택 항목으로 이동할 수 있는지 확인한다.
- 미리보기에서 `시작하기`를 눌러도 POST 요청과 DB 변경이 발생하지 않는지 확인한다.
- `미리보기 나가기`와 하드웨어·브라우저 뒤로 가기로 마이페이지에 복귀하는지 확인한다.
- 토스트의 접근성 속성, 중복 방지, 안전 영역 위치를 확인한다.
- 일반 사용자의 `/register` 제출과 검증 실패 값 복원이 기존대로 동작하는지 회귀 테스트한다.
- `npm test`, `npm run check`, `npm run build`를 실행한다.

## 제외 범위

- 관리자별 미리보기 진행 상태 저장
- 미리보기 입력값의 DB 저장 또는 분석 이벤트 전송
- 관리자별 계정 및 수정 이력 기능
- 실제 사용자 온보딩 문항과 선택 항목 변경
- 온보딩 디자인의 전면 개편

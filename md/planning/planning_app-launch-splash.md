# 앱 시작 아이콘 및 스플래시 기획

## 목적

브라우저에 남아 있는 Svelte 기본 파비콘을 골라바유 호이 핀으로 교체하고, 앱을 열 때 흰색 배경 중앙에서 호이 핀이 자연스럽게 커지는 시작 화면을 제공한다.

## 적용 범위

- 기존 `static/icon.png`를 골라바유 파비콘과 스플래시의 원본 이미지로 재사용한다.
- SvelteKit 문서가 처음 표시될 때 흰색 전체 화면 스플래시를 노출한다.
- 호이 핀은 화면 중앙에서 작은 크기로 시작해 원래 크기까지 부드럽게 확대한다.
- 애니메이션이 끝나면 스플래시 전체가 짧게 투명해진 뒤 제거되어 홈 화면을 보여 준다.
- SvelteKit의 클라이언트 내부 페이지 이동에서는 스플래시를 다시 표시하지 않는다.

## 구현 구조

### 파비콘

- `src/routes/+layout.svelte`의 Svelte 기본 파비콘 연결을 `/icon.png`로 교체한다.
- PNG 형식을 명시해 브라우저가 정적 자산을 올바르게 해석하도록 한다.
- 현재 단계에서는 별도의 앱 스토어용 Android·iOS 아이콘 세트를 생성하지 않는다.

### 시작 스플래시

- 첫 화면의 빈 프레임을 줄이기 위해 스플래시 마크업을 `src/app.html`에 둔다.
- Svelte가 초기화되기 전에도 흰색 배경과 호이 핀이 즉시 표시되도록 일반 HTML과 최소 CSS로 구성한다.
- 스플래시는 문서 최초 로드 때 한 번만 생성한다. SvelteKit 내부 탐색은 문서를 다시 만들지 않으므로 재생되지 않는다.
- 애니메이션 종료 후 요소를 제거해 숨은 레이어가 터치, 스크롤, 접근성 트리에 영향을 주지 않게 한다.

## 시각 및 동작 규칙

- 배경색은 `#ffffff`로 고정한다.
- 호이 핀은 `static/icon.png`의 비율을 유지하며 화면 중앙에 배치한다.
- 아이콘은 약 70% 크기에서 100% 크기로 확대한다.
- 전체 진입과 퇴장 시간은 약 0.8초로 유지해 앱 진입을 불필요하게 지연하지 않는다.
- 확대에는 과도한 튕김이나 회전을 사용하지 않고, 짧은 크기 및 투명도 전환만 적용한다.
- 상단과 하단 안전 영역을 포함해 화면 전체를 덮되 아이콘의 시각적 중심은 화면 중앙에 둔다.

## 접근성 및 실패 처리

- 스플래시는 장식 요소로 처리해 스크린 리더가 중복으로 읽지 않게 한다.
- `prefers-reduced-motion: reduce` 환경에서는 확대 이동을 생략하고 짧은 표시·제거만 수행한다.
- 자바스크립트 실행이 늦거나 실패하더라도 CSS 애니메이션 종료 상태에서 스플래시가 보이지 않도록 구성해 화면을 계속 가리는 상황을 막는다.
- 이미지가 로드되지 않더라도 흰색 스플래시가 짧게 사라지고 본문 진입을 방해하지 않게 한다.

## 웹 및 모바일 호환성

- 구현은 표준 HTML과 CSS를 사용해 일반 웹 브라우저와 향후 Capacitor WebView에서 동일하게 동작하게 한다.
- 현재 저장소에는 Capacitor Android·iOS 프로젝트가 없으므로 네이티브 시작 화면은 이번 범위에서 다루지 않는다.
- 추후 Capacitor를 도입할 때 네이티브 스플래시 종료 시점과 웹 스플래시 시작 시점을 맞춰 중복 노출을 방지한다.

## 검증

- 파비콘 연결이 `/icon.png`를 가리키고 Svelte 기본 아이콘 참조가 제거됐는지 자동 테스트로 확인한다.
- 시작 마크업, 아이콘 경로, 흰색 배경, 확대 애니메이션, 동작 줄이기 처리를 자동 테스트로 확인한다.
- 새 문서 진입에서는 스플래시가 한 번 재생되고 내부 페이지 이동에서는 다시 나타나지 않는지 브라우저에서 확인한다.
- `npm test`, `npm run check`, `npm run build`를 실행한다.
- 배포 후 운영 URL에서 파비콘 응답과 첫 진입 화면을 확인한다.

## 제외 범위

- Android Adaptive Icon 및 iOS App Icon 자산 생성
- Capacitor 설치와 네이티브 프로젝트 생성
- 네이티브 스플래시 설정
- 내부 페이지 전환 애니메이션
- 기존 헤더와 지도 마커의 호이 핀 표시 변경

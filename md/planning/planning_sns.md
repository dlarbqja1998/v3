# 지도 기반 SNS 기획 — 향후 실험안

## 문서 상태

- 결정일: 2026-08-11
- 상태: **현재 출시 범위에서 제외하고 보류**
- 다시 검토할 때 사용할 표현: `SNS 기획 꺼내와`, `지도 SNS 기획 다시 보자`
- 현재 우선순위: SNS 대신 건물·광장·운동장·출입구의 실용 정보 카드 구현

골라바유는 우선 학식, 셔틀, 지도, 장소 정보로 반복 사용 가치를 증명한다. SNS, 랭킹, 뱃지, 공개 사용자 게시물은 초기 출시의 필수 기능으로 보지 않는다.

### 보류한 이유

- 캠퍼스 전체 인원과 별개로 실제 현장 활동 인원이 적어 장소별 실시간 콘텐츠가 비어 보일 가능성이 크다.
- 예를 들어 실제 활동 인원 200명, 초기 앱 사용률 20%, 일일 작성률 10%를 가정하면 하루 작성물은 약 4개다. 이를 25개 장소에 나누면 장소별 피드는 며칠에 한 번 갱신되는 수준이 될 수 있다.
- 공개 SNS를 운영하려면 신고, 삭제, 차단, 도배 방지, 닉네임, 프로필, 알림, 사진 저장, 운영 정책이 함께 필요하다.
- 2026년 9월 1일 초기 홍보 목표를 고려하면 생활 기능과 장소 정보의 완성도가 우선이다.

### 현재 출시에서 대신 구현할 방향

- `지금, 공공정책관`처럼 선택한 장소명을 보여주는 최대 높이 바텀시트
- 장소 기본 안내, 운영시간, 주요 시설, 오늘의 행사
- 길 찾기, 즐겨찾기, 정보 수정 제보
- 사용자 제보는 바로 공개하지 않고 운영자 확인 후 반영하는 방식부터 검토

## 1. 제품 정의

향후 SNS를 다시 검토한다면 에브리타임과 같은 학교 전체 자유게시판을 복제하지 않는다.

> 에브리타임에서는 학교 전체의 이야기를 보고, 골라바유에서는 지금 가려는 장소의 상황을 본다.

사용자가 남긴 개별 키워드 리뷰와 짧은 글을 기본 콘텐츠로 삼되, 모든 콘텐츠는 캠퍼스 전체 피드에 먼저 모은다. 지도와 장소 바텀시트는 같은 원본 콘텐츠를 위치 기준으로 탐색하는 수단으로 사용한다. 장소별 독립 SNS는 만들지 않는다.

## 2. 핵심 원칙

- 원본은 한 명의 사용자가 남긴 `개별 리뷰`다.
- 키워드 선택이 기본이고 짧은 글과 사진은 선택 사항이다.
- 최신 개별 리뷰가 충분히 모인 장소에서만 `지금 상태` 집계를 실험한다.
- 오래된 콘텐츠를 삭제한 것처럼 숨기지 않고 `지금`, `오늘`, `최근 소식`으로 시간 표현을 바꾼다.
- 장소별 피드를 고립시키지 않고 캠퍼스 전체 피드에 먼저 노출한다.
- 초기 랭킹은 장소별이 아니라 캠퍼스 전체 기여자 랭킹으로 검토한다.
- 장소별 랭킹과 뱃지는 해당 장소에 충분한 활동량이 생긴 뒤에만 연다.
- 사용자 콘텐츠가 없어도 행사·공지와 건물 기본 정보로 빈 화면을 막는다.
- 건물, 잔디광장, 운동장, 출입구, 랜드마크에 같은 키워드를 획일적으로 제공하지 않는다.

## 3. 사용자 흐름

### 3.1 건물 선택

1. 사용자가 지도에서 `공공정책관`을 누른다.
2. 해당 건물의 중앙 핀이 남은 지도 영역인 화면 상단 1/6의 중앙으로 이동한다.
3. 바텀시트가 화면의 5/6 지점까지 최대 높이로 올라온다.
4. 제목을 `지금, 공공정책관`으로 표시한다.
5. 해당 건물을 선택한 시점에만 콘텐츠를 지연 로딩한다.

### 3.2 건물 바텀시트 확인

표시 순서는 다음과 같다.

1. 제목과 건물명
2. 최신 리뷰가 충분할 때 현재 상태 요약
3. 오늘 이곳에서 열리는 행사·공지
4. 해당 건물의 개별 키워드 리뷰와 짧은 글
5. 건물별 주간 랭커와 사용자의 다음 뱃지 진행도
6. `지금 상태 남기기` 버튼

바텀시트는 지도 탐색과 요약에 사용한다. 글 작성, 게시물 상세, 행사 상세, 사진 전체 보기는 별도 화면으로 연다.

### 3.3 리뷰 작성

1. 사용자가 `지금 상태 남기기`를 누른다.
2. 키워드를 선택한다.
3. 원할 경우 짧은 글이나 사진을 추가한다.
4. 등록 후 해당 건물 피드와 캠퍼스 전체 피드에 동시에 노출한다.
5. 기여 점수와 뱃지 진행도를 즉시 안내한다.

장소 성격에 따라 서로 다른 키워드 프로필을 제공한다. 예시는 다음과 같다.

- 강의·학업동: `붐벼요`, `조용해요`, `자리 있어요`, `냉난방 불편`
- 학습 공간: `좌석 여유`, `콘센트 자리`, `소음`, `프린터 문제`
- 잔디·광장: `사람 많아요`, `행사 중`, `잔디 상태 좋아요`
- 운동시설: `사용 가능`, `경기 중`, `바닥 상태`, `조명 켜짐`
- 출입구: `차량 막혀요`, `택시 있어요`, `승하차 혼잡`, `출입 원활`
- 랜드마크: `약속하는 사람 많아요`, `행사 중`, `촬영 중`

초기에는 건물 단위로만 받는다. 층·강의실 단위 분리는 콘텐츠가 충분히 쌓인 뒤 검토한다.

## 4. 시간과 상태 집계

초기 서비스에서는 모든 리뷰를 고정 시간 뒤 제거하지 않는다. 데이터 양과 작성 시각에 따라 표현을 바꾼다.

- 최근 리뷰가 있으면 `지금`
- 오늘 작성된 리뷰만 있으면 `오늘 공공정책관`
- 오늘 리뷰가 없으면 작성 날짜를 포함한 `최근 소식`
- 최신 리뷰가 3개 이상일 때만 키워드별 현재 상태를 집계
- 최신 리뷰가 1~2개면 합산 결과를 단정하지 않고 개별 리뷰와 작성 시각을 표시

예시 문구는 `최근 30분 동안 5명 중 3명이 붐빈다고 알려줬어요`처럼 시간과 참여 인원을 함께 보여준다.

키워드별 유효 시간은 실제 이용 데이터를 확인한 뒤 조정한다. 초기 가설은 다음과 같다.

- 혼잡도·자리: 빠르게 신뢰도가 감소하는 정보
- 분위기: 당일 안에서 참고할 수 있는 정보
- 시설 문제: 해결 확인이나 재확인이 필요한 정보
- 짧은 글·사진: 건물의 당일 흐름을 보여주는 정보

## 5. 캠퍼스 전체 피드

`오늘` 탭은 모든 건물의 최신 리뷰, 짧은 글, 사진, 행사 정보를 한곳에 모은다.

- 모든 게시물에는 건물 위치가 붙는다.
- 건물명을 누르면 지도에서 해당 건물 바텀시트를 연다.
- 건물 바텀시트에서는 같은 원본 데이터를 건물 기준으로 필터링한다.
- 초기 이용자가 적더라도 콘텐츠가 여러 건물로 완전히 분산되지 않게 한다.

## 6. 랭킹과 뱃지 — 후순위

### 6.1 랭킹

- 초기에는 콘텐츠를 장소별로 분산시키지 않도록 `캠퍼스 전체 주간 기여자 랭킹`만 검토한다.
- 특정 장소의 활동량이 기준치를 넘으면 해당 장소의 주간 랭킹을 추가한다.
- 랭킹은 매주 초기화해 신규 사용자도 참여할 수 있게 한다.
- 게시물 작성 횟수만으로 순위를 정하지 않는다.
- 다른 사용자의 `맞아요`, 중복되지 않은 최초 정보, 확인된 행사·시설 제보에 더 높은 점수를 준다.
- 같은 내용의 반복 등록과 짧은 시간의 도배에는 점수를 주지 않는다.
- 하루에 인정되는 기여 횟수를 제한한다.

### 6.2 뱃지

- 영구 업적: `첫 발견`, `행사 레이더`, `정확한 제보자`
- 건물 전문 뱃지: `공공정책관 터줏대감`, `학술정보원 지킴이`
- 기간 칭호: `이번 주 공공정책관 1위`

주간 순위는 초기화하지만 획득한 영구 뱃지와 인정받은 활동 기록은 프로필에 보존한다. 다만 랭킹과 뱃지는 실제 공개 제보가 반복적으로 발생한 뒤 도입한다.

## 7. 초기 사용자 부족 대응

- 행사·공지와 건물 기본 정보를 운영 데이터로 먼저 제공한다.
- 리뷰가 없을 때 `아직 글이 없습니다`만 보여주지 않는다.
- 리뷰 한 건도 작성 시각과 작성자를 포함한 유용한 개별 정보로 노출한다.
- 최신 리뷰가 충분하지 않으면 억지로 현재 상태를 집계하지 않는다.
- 건물별 콘텐츠를 캠퍼스 전체 피드에도 노출해 작성자의 도달 범위를 넓힌다.
- 학식·셔틀·지도라는 기존 생활 기능을 기본 재방문 이유로 유지하고, 건물 콘텐츠는 그 위에서 성장시킨다.

## 8. 신뢰와 운영

- 모든 개별 리뷰에는 작성 시각을 표시한다.
- 다른 사용자가 현재도 맞는 정보인지 확인할 수 있게 한다.
- 신고, 본인 글 삭제, 운영자 숨김 기능을 제공한다.
- 사진 업로드 수와 용량을 제한한다.
- 동일 건물·키워드의 반복 등록에는 대기 시간을 둔다.
- 위치 권한을 필수로 요구하지 않는다. 실제 이용 패턴을 본 뒤 현장 인증의 필요성을 검토한다.
- 사용자의 공개 닉네임과 뱃지 노출 범위는 계정·프로필 기획과 함께 확정한다.

## 9. 서버리스 비용 원칙

- 건물 선택 시에만 해당 건물의 최신 콘텐츠를 요청한다.
- 건물 요약, 행사, 공개 리뷰 목록은 짧은 캐시를 적용한다.
- 같은 건물의 요약과 리뷰를 가능한 한 한 번의 요청으로 제공한다.
- 목록은 커서 기반 페이지네이션을 사용하고 필요한 필드만 조회한다.
- 사진 원본은 Cloudflare R2에 저장하고 Neon에는 게시물과 이미지 메타데이터만 저장한다.
- 업로드는 가능하면 서명 URL로 R2에 직접 전송해 Worker 부하를 줄인다.
- 사용자별 순위·작성 여부처럼 캐시하면 안 되는 데이터는 공개 캐시에서 분리한다.

## 10. 향후 재검토 시 단계

### 0단계: SNS 없이 장소 정보 제공

- 건물 선택 시 바텀시트 최대 높이 전환
- 상단 1/6 중앙으로 핀 포커스
- `지금, 건물명` 제목
- 장소 기본 안내, 운영시간, 주요 시설, 행사
- 정보 수정 제보

### 1단계: 비공개 제보 수요 확인

- 시설 고장, 정보 오류, 행사, 분실물 제보
- 운영자 확인 후 정보 반영
- 장소별 제보량과 반복 참여율 측정

### 2단계: 위치가 붙은 공개 콘텐츠 실험

- 키워드 선택과 짧은 글 작성
- 캠퍼스 전체 피드에 우선 노출
- 장소 바텀시트에서는 해당 위치의 콘텐츠만 필터링
- 작성 시각에 따른 `지금`, `오늘`, `최근 소식` 표시
- 신고·삭제와 최소 도배 방지

### 3단계: 충분한 활동이 확인된 뒤 게임화

- `맞아요` 확인
- 캠퍼스 전체 주간 랭킹
- 초기 뱃지와 진행도
- 활동량이 충분한 장소만 장소별 랭킹과 전문 뱃지 제공

### 4단계: 확장

- 사진 업로드
- 행사 등록·검증
- 사용량이 많은 건물의 층·세부 장소 구분
- 실제 데이터에 근거한 키워드별 유효 시간 조정

## 11. 성공 판단 기준

단순 가입자 수보다 다음 행동을 본다.

- 건물 바텀시트를 연 사용자 중 리뷰를 확인한 비율
- 리뷰를 확인한 사용자 중 키워드를 남긴 비율
- 첫 기여 후 7일 안에 다시 기여한 비율
- 한 건의 리뷰가 받은 `맞아요` 수와 확인까지 걸린 시간
- 특정 건물에만 콘텐츠가 몰리는 정도
- 신고율과 중복·도배 차단 비율

## 12. 아직 확정할 항목

- SNS 재검토를 시작할 최소 제보량과 반복 참여율
- 리뷰 작성자의 공개 이름을 닉네임, 익명 번호, 혼합형 중 무엇으로 할지
- 키워드를 한 번에 하나만 선택할지 여러 개 선택할지
- 초기 점수표와 하루 인정 횟수
- 사진 개수·용량 제한
- 행사 등록 권한과 검증 방식
- 현재 상태 집계에 필요한 최소 리뷰 수와 시간 범위

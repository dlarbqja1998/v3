# 하단 네비게이션 기획

## 목표

하단 네비게이션은 골라바유의 주요 생활 기능으로 빠르게 이동하는 기본 앱 구조다. 지도 기반 첫 화면과 바텀시트가 이미 중심 인터페이스이므로, 하단 네비게이션은 사용자가 반복적으로 누를 핵심 기능만 간결하게 담는다.

## 1차 항목

1차 하단 네비게이션은 아래 네 항목으로 구성한다.

- 학식
- 셔틀
- 핀
- 마이

`홈` 항목은 1차에서 제외한다. 현재 메인 화면 자체가 지도 기반 홈 역할을 하고 있고, 하단 네비게이션은 사용자가 명확한 목적을 가지고 이동하는 기능 중심으로 구성하는 편이 더 선명하다.

## 항목별 동작

### 학식

- 누르면 메인 화면의 학식 영역 또는 학식 바텀시트 상태로 이동한다.
- 이미 메인 화면에 있다면 지도 위 상태를 유지하면서 학식 정보가 잘 보이는 상태로 전환한다.
- 이후 별도 학식 상세 페이지가 생기면 라우팅 방식으로 전환할 수 있다.

### 셔틀

- 누르면 셔틀 정보 영역 또는 셔틀 바텀시트 상태로 이동한다.
- 셔틀은 시간표와 정류장 정보가 함께 보이는 흐름을 우선한다.
- 이후 실시간 위치나 즐겨찾기 정류장 기능이 생기면 이 항목을 확장한다.

### 핀

- 1차에서는 항목만 먼저 둔다.
- 추후 사용자가 원하는 핀 종류를 선택하거나 직접 핀을 찍는 기능으로 확장한다.
- 초기 구현에서는 준비 중 화면, 비활성 상태, 또는 간단한 안내 바텀시트 중 하나로 처리할 수 있다.
- 로그인 또는 온보딩이 필요한 기능으로 발전할 가능성이 높으므로 권한 흐름을 열어둔다.

### 마이

- 누르면 `/my`로 이동한다.
- 로그인하지 않은 사용자는 `/login?next=/my`로 보낸다.
- 로그인 후에는 내 정보, 내 정보 수정하기, 로그아웃을 제공한다.

## 아이콘 방향

아이콘은 기존 의존성인 `lucide` 기반의 단순한 라인 아이콘을 사용한다.

- 학식: `Utensils` 또는 `Soup`
- 셔틀: `Bus`
- 핀: `MapPin`
- 마이: `User`

아이콘은 장식보다 인식성이 우선이다. 활성 항목은 브랜드 색을 사용하고, 비활성 항목은 중립 회색으로 둔다. 텍스트 라벨은 숨기지 않고 아이콘 아래에 함께 표시해 처음 쓰는 사용자도 바로 이해할 수 있게 한다.

## 배치와 레이아웃

- 하단 네비게이션은 모바일 화면 하단에 고정한다.
- WebView 출시를 고려해 `safe-area-inset-bottom`을 반영한다.
- 메인 지도 화면의 바텀시트는 네비게이션과 겹치지 않도록 하단 여백을 가진다.
- 하단 네비게이션은 화면을 과하게 가리지 않도록 높이를 작고 안정적으로 유지한다.
- 각 항목은 동일한 너비를 갖고, 터치 영역은 모바일에서 누르기 충분한 크기로 둔다.

## 현재 헤더와의 관계

메인 화면 오른쪽 위에는 긴 닉네임 버튼을 두지 않는 방향이 좋다. 닉네임이 길면 화면을 해칠 수 있고, 마이페이지 진입점으로도 덜 직관적이다.

상단 오른쪽 영역은 다음 중 하나로 단순화한다.

- 비로그인 상태에서는 `로그인` 버튼 유지
- 로그인 상태에서는 작은 프로필 아이콘 또는 짧은 상태 표시
- 마이페이지 진입은 하단 네비게이션의 `마이`로 통일

## 제외 범위

아래 항목은 1차 하단 네비게이션에서 제외한다.

- 홈
- 맛집
- 공지
- 포인트샵
- 만나볼텨
- 검색

맛집, 공지, 포인트샵, 만나볼텨는 이후 사용 흐름이 구체화되면 추가 여부를 다시 판단한다. 1차에서는 하단 네비게이션을 넓히기보다 학식, 셔틀, 핀, 마이의 의미를 분명히 하는 것이 우선이다.

## 구현 시 주의사항

- 하단 네비게이션은 여러 페이지에서 공유될 가능성이 높으므로 공통 컴포넌트로 분리하는 편이 좋다.
- 현재 선택된 항목은 URL 또는 메인 화면 상태를 기준으로 판단한다.
- 학식과 셔틀이 같은 메인 페이지 안의 상태 전환이라면 쿼리 파라미터나 내부 상태 이름을 정해 새로고침과 공유 URL을 고려한다.
- 핀은 아직 기능이 완성되지 않았으므로 사용자가 막다른 길에 도착하지 않게 준비 중 상태를 명확히 제공한다.

# 마이페이지 기획

## 목표

마이페이지는 로그인한 사용자가 자신의 기본 정보를 확인하고, 필요한 계정 동작을 수행하는 공간이다. 초기 구현에서는 커뮤니티형 활동 기록이나 포인트 내역까지 확장하지 않고, 로그인 이후 사용자가 기대하는 최소 계정 화면을 안정적으로 제공하는 데 집중한다.

## 진입 경로

- 하단 네비게이션의 `마이` 항목을 누르면 `/my`로 이동한다.
- 비로그인 사용자가 `/my`에 접근하면 `/login?next=/my`로 이동한다.
- 온보딩을 완료하지 않은 사용자가 `/my`에 접근하면 기존 보호 흐름에 따라 `/register?next=/my`로 이동한다.

메인 화면 오른쪽 위의 닉네임 버튼을 마이페이지 진입점으로 쓰는 방식은 1차 방향에서 제외한다. 닉네임 길이에 따라 헤더가 흔들릴 수 있고, 사용자가 닉네임을 눌러 마이페이지로 이동한다는 사실을 직관적으로 알기 어렵기 때문이다.

## 표시 정보

마이페이지에는 현재 로그인한 사용자의 기본 정보를 간단히 보여준다.

- 닉네임
- 단과대
- 학과
- 학번
- 성별
- 로그인 방식

로그인 방식은 초기에는 `카카오 로그인` 또는 `관리자 로그인` 수준으로만 표시한다. 계정 상태, 차단 여부, 온보딩 완료 여부 같은 항목은 일반 사용자 화면에서 별도로 강조하지 않는다. 필요한 경우 서버 보호 로직과 관리자 도구에서 다루는 편이 낫다.

## 주요 액션

### 로그아웃

- 마이페이지에 `로그아웃` 버튼을 둔다.
- 사용자가 로그아웃을 누르면 서버 액션에서 `session_id` 쿠키를 삭제한다.
- 로그아웃 후에는 메인 화면(`/`)으로 이동한다.
- 로그아웃은 되돌릴 수 없는 파괴적 작업은 아니지만, 현재 세션이 종료되는 동작이므로 버튼 문구는 명확하게 둔다.

### 내 정보 수정하기

- 마이페이지에 `내 정보 수정하기` 진입 버튼을 둔다.
- `내 정보 수정하기`는 별도 `/my/edit` 페이지로 이동한다.
- `/my/edit`은 `/register`의 입력 검증과 선택지 구조를 재사용하되, 이미 저장된 사용자 값을 기본값으로 보여준다.
- 수정 가능한 항목은 닉네임, 단과대, 학과, 학번, 성별로 둔다.
- 닉네임은 기존 온보딩과 동일하게 중복 검증을 적용한다.

## 화면 구조 초안

마이페이지는 모바일 우선 화면으로 구성한다.

1. 상단 영역
   - 페이지 제목 `마이`
   - 짧은 인사 문구 또는 닉네임 중심 요약
2. 내 정보 영역
   - 정보 항목을 읽기 쉬운 목록 형태로 표시
   - 값이 없는 항목은 `미입력` 대신 온보딩 보호 흐름으로 해결하는 것을 기본으로 한다.
3. 계정 액션 영역
   - `내 정보 수정하기`
   - `로그아웃`

하단 네비게이션이 있는 화면이므로 마지막 영역은 안전 영역과 네비게이션 높이만큼 여백을 둔다.

## 제외 범위

아래 항목은 1차 마이페이지 구현에서 제외한다.

- 내가 쓴 글 목록
- 내가 찍은 핀 목록
- 포인트 또는 활동 기록
- 알림 설정
- 프로필 이미지 변경
- 계정 탈퇴
- 차단 또는 계정 상태 표시

## 구현 시 주의사항

- 서버에서 `locals.user`를 기준으로 접근을 제어한다.
- 클라이언트에 민감한 인증 토큰이나 세션 원문을 노출하지 않는다.
- 로그아웃은 서버 액션으로 처리하고, 클라이언트 상태만 지우는 방식으로 끝내지 않는다.
- WebView 앱 환경을 고려해 하단 안전 영역과 뒤로 가기 흐름을 확인한다.

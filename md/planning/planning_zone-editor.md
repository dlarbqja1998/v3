# 관리자 상권 구역 편집기 기획

## 목적

관리자가 지도에서 `조치원역`, `고대앞`, `홍대사이` 같은 상권 구역을 먼저 생성하고, 이미 저장된 구역의 목록을 확인하거나 경계를 수정할 수 있게 한다. 음식점 데이터가 아직 없어도 구역은 독립적으로 생성할 수 있어야 한다.

## 현재 구조

- `campus_spots`: 학교 건물, 야외 공간, 랜드마크의 실제 경계를 저장한다.
- `zones`: 상권이나 생활권의 이름, 지도 경계, 중심 좌표를 저장한다.
- `places`: 음식점·카페 같은 개별 장소를 저장하며 `zone_id`로 한 구역에 연결된다.
- 현재 `/admin/boundary-editor`는 `campus_spots`의 기존 경계 수정만 지원한다.

## 검토한 접근 방식

### 1. 기존 화면에 두 편집 모드 추가 — 채택

`캠퍼스 장소`와 `상권 구역` 탭을 두고 같은 지도와 경계 편집 방식을 공유한다. 관리자가 한 화면에서 지도 데이터를 관리할 수 있고, 기존 캠퍼스 경계 편집 기능도 유지된다.

### 2. 별도 `/admin/zone-editor` 화면 추가

구조는 가장 명확하지만 지도 SDK 로딩과 편집 UI가 중복된다. 현재 기능 규모에서는 관리 화면이 불필요하게 나뉜다.

### 3. 캠퍼스 장소와 상권 구역을 하나의 목록으로 통합

화면은 단순해 보이지만 서로 다른 테이블과 의미를 섞게 된다. 잘못된 데이터 수정 가능성이 커서 채택하지 않는다.

## 화면 설계

### 캠퍼스 장소 모드

- 현재 기능을 그대로 유지한다.
- 기존 캠퍼스 장소를 선택하고 경계 꼭짓점을 추가·이동·삭제한 뒤 저장한다.

### 상권 구역 모드

- DB에 저장된 모든 구역을 목록으로 표시한다.
- 각 항목에는 구역 이름을 표시한다.
- 기존 구역을 선택하면 이름과 지도 경계를 불러온다.
- `새 구역 만들기`를 누르면 이름과 경계가 비어 있는 생성 상태로 전환한다.
- 생성 상태에서는 지도 클릭 순서대로 경계 꼭짓점을 만든다.
- 꼭짓점이 3개 이상일 때만 저장할 수 있다.
- 저장 후 생성된 구역을 선택 상태로 유지하고 목록에 즉시 반영한다.

## 저장 규칙

- 이름은 앞뒤 공백을 제거하고 비어 있으면 저장하지 않는다.
- 동일한 이름의 구역이 이미 있으면 자동 덮어쓰지 않고 오류를 보여준다.
- 신규 구역에는 서버에서 고유한 영문 식별자(`slug`)를 생성한다.
- 이름에서 안정적인 영문 식별자를 만들기 어려운 경우 `zone-<짧은 UUID>` 형식을 사용한다.
- 수정은 구역 UUID를 기준으로 수행하므로 이름을 바꾸더라도 신규 행이 생기지 않는다.
- 경계의 중심 좌표는 서버에서 계산해 `center_latitude`, `center_longitude`에 저장한다.
- 경계는 최소 3개의 유효한 위도·경도 좌표여야 한다.
- 신규 생성과 수정은 서로 다른 서버 액션으로 분리한다.

## 데이터 흐름

1. 관리자만 페이지에 접근한다.
2. 서버 로드에서 `campus_spots`와 `zones`를 각각 조회한다.
3. 사용자가 모드를 선택하고 지도에서 경계를 편집한다.
4. 신규 저장 시 서버가 이름 중복을 확인하고 `zones`에 새 행을 추가한다.
5. 수정 저장 시 서버가 UUID로 기존 구역을 찾아 이름·경계·중심 좌표를 갱신한다.
6. 저장 성공 후 페이지 데이터를 다시 로드해 DB 기준 목록과 편집 상태를 동기화한다.

## 오류 처리

- 비로그인 사용자는 로그인 화면으로, 일반 사용자는 메인 화면으로 이동한다.
- 이름 누락, 잘못된 JSON, 3개 미만의 꼭짓점은 `400` 오류로 처리한다.
- 같은 이름의 구역은 `409` 오류로 처리하고 기존 구역을 선택해 수정하도록 안내한다.
- 존재하지 않는 UUID 수정은 `404` 오류로 처리한다.
- DB 오류가 나면 입력 중인 경계는 화면에 유지하고 일반 오류 문구를 보여준다.

## 테스트 범위

- 구역 이름 정규화와 중복 판정
- 유효한 경계 중심 좌표 계산
- 신규 구역 저장 데이터 생성
- 기존 구역 수정 시 UUID 기준 갱신
- 이름 누락·경계 부족·중복 이름 오류
- 관리자 권한 검사
- Svelte 및 TypeScript 정적 검사
